# 首页场景化改造设计（2026-09-01）

## 背景与问题

Gwork 官网首页（`src/pages/Home.tsx`）当前以「安全能力」为主线：Hero 区约 60% 内容为安全相关（安全信号卡、安全中心浮动卡、「本地优先·安全可控」眉题），亮点条 2/3 安全，指标条 2/4 安全，另有一整块「安全合规区」。安全只是产品的支撑属性，政企采购决策者真正关心的是「能帮我解决什么活」：公文起草、会议纪要、材料整理、制度问答、周报汇总。安全应从主角降为背书，场景从配角升为主角。

同时场景页（`src/pages/Scenarios.tsx`）第 4 个场景「本地安全办公」同样是安全导向，与首页问题一致，需一并调整。

## 竞品分析

### DuMate（百度搭子）
- 定位：「真干活，用搭子」，跨应用、跨文件，复杂任务一句话搞定
- 卖点：杂乱文件夹秒变知识库 / 重复操作变自动化 / 零门槛上手 / 本地运行数据不外流
- 风格：大白话短句、亲民「搭子」人设、百度账号 + 积分体系

### WorkBuddy（腾讯云）
- 定位：「AI Agent 办公新范式」，腾讯全场景 AI 办公工作台
- 卖点：深度调研 15 分钟出报告 / 多 Agents 并行 / 打通腾讯生态（微信、腾讯文档、腾讯会议、QQ 邮箱）/ 积分订阅制
- 风格：大厂生态绑定、积分订阅、案例堆料、ToB 销售导向

### 共性 = Gwork 差异化空间

| 维度 | DuMate / WorkBuddy | Gwork |
|---|---|---|
| 场景 | 泛办公效率，「什么活都能干」 | 政企材料场景：公文起草 / 纪要 / 制度问答，有公文体例能力 |
| 部署 | 云上助手，数据上传 + 账号积分 | 本机运行：数据留在本机，可接内网模型 |
| 计费 | 积分制 / 订阅制 | 免费安装，模型自带 key 接入 |
| 模型 | 厂商锁定 | DeepSeek / 通义 / 智谱 / Kimi 自由选，可接自采政务云模型 |
| 受众 | 小白向，「解放双手」「一句话搞定」 | 专业办公人员，「把活干明白」 |

**差异化定位一句话**：竞品面向小白讲「解放双手」，Gwork 面向专业办公人员讲「把活干明白」——不抢「一句话搞定」话术，讲「交付什么质量的成果」：按体例起草、带出处回答、自动定时执行、可控可审计。专业与强大全部落到场景点上。

## 设计目标

1. 首页从安全导向转为场景导向，场景为主角，安全降为背书
2. 与竞品做出差异：专业、强大、政企材料场景
3. 说人话：面向公职/办公人员，不暴露技术术语
4. 首页与场景页分工：首页场景预览，场景页场景详解，不重复
5. 文案真实性红线：不写「一键生成规范 Word」（官方格式导出未完全打通）；知识库「回答带出处」为真实能力

## 新首页结构（7 段）与全文案

### ① Hero（重写）

- eyebrow：`政企办公 · 专业助手`
- H1：**「专业的事，交给专业的 AI 助手」**（套用「专业的事交给专业的人」句式，辉哥定稿）
- 副标题：「公文起草、材料整理、制度问答、周报汇总——不是聊天式问答，而是按政企工作习惯交付：按体例起草、带出处回答、到点自动执行。数据留在本机，模型可接内网，无需注册、无需积分。」
- CTA：`下载 Gwork` + `了解功能 →`（保留）
- chips（4 个）：`按体例起草公文` / `回答带出处` / `数据留在本机` / `支持 macOS 与 Windows`（定稿用「与」，说人话）
- 浮动卡片：标题 `通知初稿`，副文 `已按公文体例起草`
- mini-panel 保留：政务写作 / 知识问答 / 定时任务
- **删除**：安全信号卡（命令审批 / 网络规则 / 操作审计 3 项），压缩进⑤的一句话

### ② 场景区（新增，顶替原「亮点条 + 指标条」）

眉题：`典型场景`；标题：`从案头到交付，办公的事都帮得上忙`（定稿，辉哥 9/1 定：覆盖公文、产品文档、原型设计等广泛办公产出）；描述：`四个高频场景，覆盖政企办公日常。`

4 张场景卡（每卡 = 场景名 + 一句痛点产出 + 3 个真实功能点，链接 `./scenarios.html#<anchor>`）。功能点全部为已验证的真实能力（见措辞红线）：

1. `政务公文写作`——通知、纪要、报告，按体例起草润色，格式少返工
   - 公文助手：一句话交代任务，按公文体例起草、润色、列提纲
   - 多助手协同：材料归集、要点提取交给子助手并行跑
   - 文件浏览：本地文件直接引用，附件随手插入
2. `企业知识库问答`——制度、资料进本地知识库，随问随答、回答带出处
   - 多知识库：按部门、按制度类型分开建库，互不串扰
   - 知识图谱：资料关系一目了然，顺藤摸瓜找依据
   - 回答带出处：引用来源可查，回答有据可依
3. `多助手材料整理`——复杂材料拆开并行，主助手统一汇总，不用自己来回切
   - 子智能体：检索、整理、润色各领一摊，互不干扰
   - 多任务并行：多线同时跑，不等不堵
   - 多标签工作区：任务独立成页，跨页随时调用
4. `定时任务`——周报汇总、资料归档，到点自动跑，不用记着
   - 到点自动执行：设置好就忘，结果自动交付
   - 执行记录可回溯：跑了什么、结果如何，随时查看
   - 多任务编排：多个定时任务各管各的，互不影响（定稿措辞，避免夸大并行/串行调度能力）

## 措辞红线

- 公文可写「起草 / 润色 / 提纲」；**不写**「一键生成规范 Word」——官方格式导出未完全打通（Word 渲染归 gwork #59 待做，external skill 分叉）
- 知识库可写「回答带出处、有据可依」——真实能力
- 场景卡功能点全部经 gwork 源码核验为真实能力：多知识库（`kb-manager.ts`）、知识图谱（`GraphView.tsx`）、公文助手（government-secretary skill）、子智能体（`src/main/subagent/`）、多任务并行与多标签工作区（gateway tab）、定时任务（`automation-scheduler.ts`）、文件浏览（workspace 文件树 + file 工具）
- 不写「解放双手 / 极致提效 / 一句话搞定」——竞品话术，不抢
- 安全措辞降级：不写「安全是第一优先级」，改为「安全是底线不是卖点」
